PKGの仕組みと運用ガイド

Google Driveに置いた記事をRaspberry Pi 5が取り込み、Geminiで整理。人間が承認した情報だけを本番Obsidianへ反映し、Windowsへ同期する仕組みです。

取り込み・AI処理・通知まで自動化済み

資料の基準：構築メモの「2026-10-01 追記⑤」まで。実装・検証状況は文書の記録に基づきます。

全体の流れ役割分担安全対策自動実行使い方完了・残課題
01 / OVERVIEW

情報が本番ノートになるまで

1 → 保存Driveへ記事を置く

Outpost Uploads / PKG-InboxにMarkdownまたはプレーンテキストを保存。

2 → 取り込みPiのinboxへ取得

drive_importer.pyが取得。既知の同名ファイルはスキップ。

3 → AI整理Geminiで構造化

processor.pyが要約・要点・分類・タグ・次の行動をJSONで受け取り、Markdown化。

4 → 承認待ちprocessedへ保存

成功した原文はarchiveへ移動。処理失敗時はinboxに原文を残す。

5 → 通知Todoist・カレンダー

Todoistで承認待ち件数を管理。夜は承認待ちがあれば確認予定を作成。

6 → 人間が判断Webで承認・却下

/promoteで内容を確認。承認時には内容の一致と秘密情報の判定を行う。

7 → 本番反映sources/pkgへコピー

許可された保存先にだけ反映。既存ファイルの上書きは拒否。

8 → 端末同期Windowsへ同期

Syncthingが本番Vaultを同期。Piへの反映とWindows同期は別の状態として表示。

通知は承認待ちを知らせる補助です。承認・却下の正本はPKGatewayにあり、Todoistの完了操作やカレンダー操作だけで本番反映は行いません。
02 / ARCHITECTURE

3つの役割を分けて動かす

取り込み・AI整理

Workbench内のPKGスクリプトがDriveとGeminiに接続。作業中の情報を、本番Vaultから分離して処理します。

承認・安全な反映

PKGatewayが検索、内容確認、承認・却下、昇格と記録を担当。本体は外部ネットワーク呼び出しを行いません。

通知・同期監視

パッケージ外のopsスクリプトが外部APIに接続。同期監視はJSONスナップショットを生成し、本体はそれを読むだけです。

03 / SAFETY

本番に入れる直前で確かめる

内容と保存先を守る

  • 確認した版に対して承認：表示時のSHA-256と実行時の内容を照合。閲覧後に変わっていたら承認・却下を拒否します。
  • 秘密情報は承認を停止：SECRET／CRITICAL判定は本番への昇格をブロック。メールアドレスの検出だけでは停止しません。
  • 書き込み範囲を限定：processedからsources/pkgへの反映に限定。既存ファイルを上書きせず、atomicコピーとハッシュで整合性を確認します。

失敗と状態の誤認を防ぐ

  • 記録漏れを修復：list_pending()時にreconcile()が本番ファイルと決定ログを照合し、コピー成功後のログ欠落を補完します。
  • 反映と同期を分離：Piへの保存成功とWindowsの同期状態を別表示。スナップショットの欠落・破損・20分以上の古さは「確認できませんでした」と表示します。
  • アクセス制御：Tailscale内のWeb画面に限定し、CSRF対策・レート制限を適用します。
確認範囲：承認時の秘密情報ブロックは実装記録があります。一方、Gemini送信前の秘密情報チェックが取り込み経路のどこに入るかは、参照したメモだけでは確定できません。
04 / AUTOMATION

5つのタイマーで役割を分担

/usr/local/sbin/pkg-ingestがpi5ユーザーで取り込み→AI処理を実行。取り込み失敗時も既存inboxを処理。Todoistに「PKG：承認待ちN件を確認」を作成・更新。0件で完了。承認待ちが1件以上なら、その日1回だけ確認予定を作成。Syncthing REST APIからWindowsの同期状況を取得し、JSONを更新。本番Vaultをborgでバックアップ。
タイマー実行間隔動作
pkg-ingest.timer10分
pkgateway-notify.timer10分
pkgateway-notify-calendar.timer毎日21:00 JST
pkgateway-sync-status.timer10分
pkgateway-backup.timer毎日

取り込み・通知・同期監視は独立したタイマーです。10分は各ジョブの起動間隔で、投入から通知までの完了時間を保証するものではありません。同一の取り込みunitは実行中に二重起動しません。

05 / DAILY USE

普段の作業は「入れる → 確認する」

  1. 記事を保存：AIで整理したいMarkdown／テキストをPKG-Inboxへ置きます。
  2. 通知を受け取る：定期処理後、Todoistの集約タスクなどから承認待ちを確認します。
  3. 内容を判断：Tailscale経由で/promoteを開き、整理結果を見て承認・却下します。
  4. 反映を確認：承認後、Piへの反映とWindowsへの同期状況を確認します。
うまく進まないときの切り分け
  • 記事が承認待ちに出ない：入力形式、同名スキップ、取り込み・AI処理のログを確認。
  • 承認時に内容変更の表示：画面を開き直して内容を再確認。
  • 秘密情報で承認できない：検出内容を確認し、元のノートの扱いを判断。
  • Piに反映済みなのにWindowsにない：Syncthingの接続・同期状態を確認。
  • 同期状況が確認不能：監視タイマーとスナップショットの更新状態を確認。
